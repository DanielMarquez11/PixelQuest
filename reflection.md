# Reflectie

1. Wat is het verschil tussen Watch, Star en Fork?
    1. Watch: je houdt de pagina in de gaten en die komt dan op je eigen account bij watch te staan.
   2. Star: Dan vindt je de repository leuk en maak je hem een van je favoriete repo's
   3. Fork: dit is eigenlijk de repository kopiëren
2. Waarom zijn Issues nuttig in een softwareproject?
    - Zo kan je bij houden wie wat waar aan werkt en zo houdt je de progress bij van het software project
3. Hoe helpen Labels en Milestones bij projectbeheer? 
   - labels zorgen voor duidelijk aan een taak van iemand wat de category van die taak is
   - Milestones: zorgen dat het optijd klaar is of in ieder geval ziet hoeveel en hoelang je er voor hebt en je kan er bepaalde doelen stellen.
   - Issues: zijn de taken die je moet oplossen binnen een software project
4. Waarom controleer je een Pull Request voor je die merge?
   - Om te zien of er geen merge conflicten aanwezig zijn. Meer een controleer punt.
5. Wat is het verschil tussen Raw, History en Blame?
   1. Raw: is code zien zonder structuur of mooie kleurtjes je ziet alles in een tekst bestand.
   2. History: je ziet precies wat er binnen die branch of commit is gedaan eraan.
   3. Blame: Hiermee zie je exact wie wat en wanneer eraan heeft gewerkt en veranderd aan het bestand en op welke regel.
6. Wanneer zou je een Wiki gebruiken in plaats van een README?
   - Als je als bedrijf iedereen moet op de hoogte stellen en wat niet direct aan je code is gekoppeld
7. Wat doet GitHub Pages?
8. - Is een gratis hostingservice van GitHub waarmee je rechtstreeks vanuit een code-repository een website kunt publiceren
